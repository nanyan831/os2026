## 二、整理后的复现提示词

以下内容根据实验目标、源码和本机验证过程整理，适用于重新执行本实验；**不是某次历史输入的逐字记录**。报告中的“最终提示词”引用的是这类复现说明。

```text
[GOAL]
阅读课程 Lab 1 指导书，在现有起始代码基础上完成最小可执行内核实验、
真实 Ubuntu 验证以及符合课程模板的实验报告。

[CONTEXT]
- 小组仓库为 https://github.com/nanyan831/os2026，实验分支名为 lab1。
- code/ 保存源代码，report/ 保存 report.md、prompt.md 和 images/。
- 使用 Ubuntu 22.04、RISC-V 交叉编译器、QEMU 和 GDB。
- Lab 1 包含入口汇编分析和 GDB 启动流程验证两项练习。
- 王子卓负责练习一，缪臻负责练习二，刘宸旭负责统筹。

[SPECIFICATION]
1. 阅读 entry.S、kernel.ld、init.c、SBI 和控制台输出源码，说明完整执行流。
2. 解释 la sp, bootstacktop 与 tail kern_init 的操作和目的。
3. 实际在 Ubuntu 编译运行，不能只根据指导书推测成功。
4. 使用 GDB 核对复位 ROM、OpenSBI、内核入口、栈设置和 C 入口。
5. 对本次配置记录 0x1000、0x80000000、0x80200000 的启动路径；
   检查 sp 是否等于当前构建的 bootstacktop，符号地址以实测为准。
6. 若 QEMU/固件行为与讲义命令不同，根据 Next Address 和断点证据定位；
   用 -kernel 指定内核，并支持 gdb-multiarch 回退。
7. 截取真实 Ubuntu 终端画面，报告引用 report/images/ 中的实际图片。
8. 按课程模板解释核心函数、整体逻辑、迭代过程和 OS 知识点。
9. 如实记录 edata/end 和 BSS 长度，不编造非空清零过程或不存在的评分结果。
10. 汇总已记录的提示词，区别用户原文、需求摘要和整理后的复现提示词。

[OUTPUT]
- 可编译、可运行的 code/；
- report/report.md；
- report/prompt.md；
- report/images/ 中的真实测试截图。

[CONSTRAINT]
- 不虚构测试结果、个人分工或逐字提示词记录。
- 不修改与实验无关的内核逻辑。
- 核心结论应由源码、反汇编或实际输出支持。
```

## 三、提示词要求与实际迭代的对应

| 要求 | 实际处理 |
|---|---|
| 阅读指导书、完成两项练习 | 分析入口汇编、链接布局及启动流程 |
| 必须实际运行 | 在 Ubuntu 使用交叉编译器、QEMU 和 GDB 验证 |
| 固件未进入内核 | 核对 Next Address，适配为 `-kernel` 启动 |
| 专用 GDB 不可用 | 使用 `gdb-multiarch` 回退 |
| 真实截图 | 在 Ubuntu X11 会话中截取实际 xterm 窗口 |
| 课程模板报告 | 报告包含成员、分工、环境、整体逻辑、实现、测试与总结 |
| 统一交付结构 | 使用 `lab1` 分支与 `code/`、`report/` 两个交付目录 |

以上迭代中，部分工具参数定位与调整由 Codex 在原任务授权范围内执行，并非每个调整都有额外一条用户提示词。
